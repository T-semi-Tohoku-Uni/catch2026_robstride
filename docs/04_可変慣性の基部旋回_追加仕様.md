## 1. 元説明書に対する変更点

電流モード＋外側の軌道追従＋ESOという基本方針は維持する。ただし「固定b0のESOに慣性変動をすべて吸収させる」ことを高速運転の前提にしない。姿勢から分かる慣性変化は公称モデルで先回りし、ESOにはモデル誤差・摩擦・未補償の軸間干渉を担当させる。

| 元説明書の項目 | 追加条件・変更 |
|---|---|
| 4.2：固定b0の軌道追従 | 姿勢に応じたb0の有界・連続スケジューリングを追加候補とする。ESO側も同じモデルを使う |
| 4.3：固定Vmax/Amax/jerk上限 | 電流・制動余裕と、移動中に到達し得る慣性上限で制約を決める |
| 4.4：FF電流変化率 ≈ jerk/b0 | b0変化時は `di_ff/dt = jerk/b0 - ad*(db0/dt)/b0^2` になる |
| 5：ESO | b0や既知動力学項の変更に伴う外乱状態の定義変更、補償量制限を追加 |
| 6：zetaを2→1方向へ下げる候補 | 最小・最大慣性、モデル誤差、同時動作を確認してから行う。一姿勢の結果を全姿勢へ外挿しない |
| 9：試験 | 固定姿勢だけでなく、旋回中の伸縮・負荷変化・姿勢情報失効を追加 |

元説明書にある `b0=10`、`Amax=3 rad/s²` 等は、姿勢別の実機確認なしに全姿勢へ採用しない。速度優先でも、電流飽和した状態を高帯域ESOで押し切らない。

## 2. 物理モデルと座標

基部角度をtheta、他の独立関節座標をs、全座標をqとする。剛体多関節モデルは [R1]：

```text
M(q) qdd + C(q,qd) qd + g(q) + tau_f = tau

基部の行：
M00(q) theta_dd + sum_j>0 M0j(q) s_dd_j
  + [C(q,qd) qd]_0 + g0(q) + tau_f0 = Ktau * iq
```

以下の簡略モデルは、他軸が保持される、または他軸の運動を与えられる条件で用いる。

```text
J(q) theta_dd = Ktau * iq - tau_coupling - tau_friction - tau_external
b(q) = Ktau / J(q) > 0
```

Ktauは基部の対象座標に換算したトルク／電流係数、Jは同じ座標に換算した慣性。CyberGear出力軸角度と基部角度が追加のベルト・ギヤで異なる場合、角度・速度・トルク・慣性の座標を統一する。ロータ慣性の出力側換算には減速比の二乗が現れる [R4]。

注意：他軸が自由に加速する場合の瞬時入力ゲインは一般に `Ktau * (M^-1)00` であり、`Ktau/M00`とは一致しない。他軸の有限な保持剛性、速度制御、柔軟性も基部から見た動特性を変える。保持姿勢で同定したJだけで同時動作を完全に記述できるとは考えない [R1][R2]。

基部が鉛直軸まわりの純粋な旋回で、旋回によって高さが変わらなければ、重力の基部軸トルクは理想的にはゼロ。水平軸・傾斜軸の場合にはこの仮定を使わない。

## 3. ESOが補えるものと補えないもの

ADRCの総外乱の定義 [R5] を、本用途へ展開すると：

```text
theta_dd = b(q) * iq + f_phys
         = b0 * iq + f_total
f_total = f_phys + (b(q) - b0) * iq
```

固定b0では：

```text
df_total/dt = df_phys/dt + (db/dt)*iq + (b-b0)*(diq/dt)
```

慣性の変化が大きいだけでなく、姿勢変化が速い、あるいは電流を速く変えるほどESOが追うべき信号の変化率が増える。ESOゲインの増加には量子化・ノイズ・遅延とのトレードオフがある [R6][R7]。

総外乱には慣性不一致も含まれるので、外乱補償が大きいことだけを「外力が大きい」「衝突した」と判定してはならない。またESOだけでJを一意に同定したことにもならない。未知外力と未知入力ゲインは、十分な励起や追加情報なしには分離できない。

観測器の入力は引き続き制限後・送信状況を反映した電流推定値を使う。停止、通信断、飽和を「外乱推定値を大きくすれば解決する問題」として扱わない [R8]。

## 4. 制御用慣性と軌道制約用慣性を分離する

### 4.1 制御用：中央推定値

```text
J_hat = bounded_model(measured_posture, payload_estimate)
b0 = Ktau / J_hat
u_acc = ad + wc^2*(qd-z1) + 2*zeta*wc*(vd-z2)
i_req = u_acc/b0 + bounded_compensation(-gamma*z3/b0)
```

推奨する最小モデルは、CADまたはリンク重量・重心位置から算出した概算に、数点の実測補正を加えたもの。姿勢固定時の基部軸慣性は、各旋回部品の重心まわりの軸方向慣性と `m*r_perp²` を合算して概算できる。姿勢の実測値を使い、未到達の目標角を実姿勢の代用にしない。大きさが無視できない荷物には荷物自体の重心まわり慣性も加える [R2][R4]。

制御則の考え方は、慣性モデルで加速度指令をトルクへ変換するcomputed-torque型制御に対応する。ただし本改修では全関節の逆動力学制御へ拡大せず、基部軸の公称モデルだけを使う [R3]。

まずwc、zeta、woは一式を固定し、b0だけのスケジュールと軌道制約を検証する。Jが大きいからといってwcやwoも比例増加させない。姿勢補間は連続に行い、上下限・変化率・情報鮮度を確認する。少数の代表姿勢点は初期モデルであり、姿勢空間全域を保証するものではない。

### 4.2 軌道用：保守的な上限

`J_hi`は、モデル誤差・搭載質量の不確かさ・その後の姿勢変化を含む慣性上限である。`J_hat`と同じ値にしない。

```text
tau_for_tracking = max(0, tau_available - tau_coupling_bound - tau_reserve)
Amax <= tau_for_tracking / J_hi
```

トルク余裕には摩擦等の必要量、モデル残差、姿勢情報遅延、追従修正分を含める。加速と減速は別の上限を持たせ、速度・温度・電源条件で利用可能トルクが変わる可能性を考慮する [R9]。

移動開始時のJだけで全軌道を検証しない。他軸の将来軌道が取れなければ、到達可能な姿勢・最大想定荷物を含むJ_hiで制約を作る。将来情報を利用する高度化は別段階。実測姿勢で必要なら再計画するが、qd/vd/adの連続性を壊さない。加速能力が低下した瞬間にadをクリップするだけの実装は禁止する。

**J_hiを制御ゲイン計算にも無条件使用してはいけない。** 重い姿勢用の大きな電流ゲインを軽い姿勢へ適用すると、サンプル遅延や共振に対する余裕が変わる。

## 5. 固定ゲインの安定性を一姿勢から外挿しない

ESOを外した、一定J・剛体・非飽和・無遅延のPDモデルを考える。設計慣性をJ0、rho=J0/Jとすると、モデルから以下を導ける。

```text
実際の自然角周波数 = wc * sqrt(rho)
実際の減衰比       = zeta * sqrt(rho)
```

仮にJがJ0の10倍なら、自然角周波数と減衰比はそれぞれ約0.316倍になる。一方でJが小さい場合、理想モデルでは減衰比も大きくなるため、「軽いほど必ず低減衰になる」という説明は誤り。ただし実機は離散制御・観測遅延・柔軟モードを含み、軽い姿勢で上昇する応答周波数も検証が必要になる [R3][R7]。

この式は現行ADRC全体の安定性定理ではない。また、各固定姿勢で安定でも、スケジューラを速く変化させた系の安定性は自動的には保証されない。姿勢遷移そのものを試験する。

## 6. b0変更時のESO状態と二重補償

### 6.1 b0を変えると総外乱の定義も変わる

同じ物理状態・同じ入力で公称ゲインだけをoldからnewへ変更する際、予測加速度を連続にする整合条件は：

```text
f_new = f_old + (b_old - b_new) * i_applied_est
```

この変換は `b_new*i + f_new = b_old*i + f_old` から導く。位置・速度状態はそのまま保持する。毎周期z3をゼロへ戻してはならない。実際の急な荷物変化や衝撃までこの式で解消できるわけではない。

入力履歴とモデル係数の時刻を合わせる。直前の区間のESO予測に、区間終了後の新しいb0を遡及適用しない。モデル更新とz3再表現は一つの整合した処理とする。

gammaが1でない場合や補償上限・電流飽和がある場合、この状態変換だけでは出力電流の連続性を保証しない。出力のbumpless transfer、レート制限、補償量の制限と合わせてテストする [R8]。

### 6.2 既知の軸間干渉をFFする場合

第1段階はb0の姿勢補正だけとし、軸間干渉は総外乱へ残す。将来、既知の軸間トルクをFFする場合は、観測器のモデルも変更する。

```text
g_model = -tau_coupling_hat / J_hat
theta_dd = b0*i + g_model + f_residual
ESOの予測加速度 = b0*i_applied_est + g_model + z3
制御入力 = (u_acc - g_model - gamma*z3)/b0   # 実際には補償・電流制限を追加
```

既存の「全外乱ESO」を変えずに、同じ軸間トルクFFだけを追加すると二重補償になり得る。g_modelも更新する場合の状態再表現は：

```text
f_new = f_old + (b_old-b_new)*i_applied_est + g_old-g_new
```

物理モデルを追加したときには、どの項が既知入力でどの項が残差外乱なのかを必ず文書化する。

## 7. 旋回中の伸縮：dot(J)と軸間干渉

鉛直軸の旋回が循環座標であり、基部との交差運動エネルギーを無視でき、旋回の運動エネルギーが `T=0.5*J(s)*theta_dot²` と書ける簡略条件では [R1]：

```text
tau_base = d(J*theta_dot)/dt
         = J*theta_dd + J_dot*theta_dot
```

一定角速度でも、アームを伸ばしてJを増やすには追加の基部トルクが必要。外部の基部トルクがゼロなら、縮めてJを減らすと角速度は増える。一般機構では、この式だけでなく2章のM0j・C・重力等を使う。`J_dot*theta_dot`を一般式のC項にさらに重ねて数えない。

また、Ktau一定・慣性FFのみなら：

```text
i_ff = J_hat * ad / Ktau
di_ff/dt = (J_hat * jerk_d + J_hat_dot * ad) / Ktau
```

慣性変動時には、参照jerkだけを制限してもFF電流の変化率を制限したことにならない。干渉トルクFFまで入れる場合はその時間微分も加わる。角度フィードバックの生の二階差分から干渉FFを作らず、検証済みの軌道情報・フィルタ推定を使う。

## 8. 柔軟振動・停止余裕・電力

慣性が大きく変化するアームでは、単一剛体モデルだけでなく、基部伝達のねじれ、リンクのたわみ、ガタを含む柔軟モードを確認する。2慣性系では共振が制御性能を制限し、モーター側だけの測定と負荷側の測定では得られる情報も違う [R10]。

長い姿勢で先端だけが振れても、モーター角度が同じように振れるとは限らない。既存の角度測定だけでの制御は維持してよいが、実機評価では動画などで先端の残留振動も確認する。wo増加や鋭い固定ノッチを共振周波数の測定なしで導入しない。最も低い構造モードを持つ姿勢で、低いjerk・適切な帯域を検証する。

制動距離の瞬時一定減速モデルは `Dstop=v²/(2*a_brake)`。例としてv=1.5 rad/s、a_brake=3 rad/s²なら0.375 rad（約21.5度）。同じトルクでJが4倍なら減速能力は1/4、理想制動距離は1.5 rad（約85.9度）。これは遅延と電流スルーを無視した計算例であり、必要な余裕の下限的な目安にしかならない。

実装では元説明書の停止余裕式を維持し、制動中の姿勢変化、通信遅延、電流反転、利用可能トルク下限を含める。駆動停止やiq=0を、能動制動の代わりと解釈しない。電源断・CAN断時に通常時の制動能力を仮定しない。

姿勢固定の旋回エネルギーは `E=0.5*J*v²`。減速時にこのエネルギーをどこで消費・回収するか、電源電圧上昇・温度上昇が許容されるかを実機の確認事項にする。旋回と他軸の同時動作ではエネルギー授受も加わる。

オーバーシュート許容は、持続・増大振動や機械可動域逸脱の許容ではない。先端水平半径rでの旋回角誤差delta_thetaは、小角近似で `delta_x≈r*delta_theta`。同じ角度誤差でも伸ばした姿勢ほど先端変位が大きいため、作業完了判定は実際の作業余裕から決める。

## 9. 実機時間を抑える同定・試験

まずCAD・重量情報でJの大まかな範囲を作る。モデル精度よりも、慣性比の桁と最悪条件の把握を優先する。機構が複雑であれば「格納／中間／伸長」の3点は開始点であって、必ずしも最大・最小慣性を含まない。

機体の安全域・低エネルギー条件・停止経路を先に確保したうえで、代表姿勢・最大想定荷物の条件で小さな電流変化に対する応答を確認する。位置だけで評価する場合は局所二次当てはめ、速度を利用できる場合は局所直線当てはめ等を用い、量子化を増幅する生の二階差分を避ける。

```text
b_effective ≈ Delta(angular_acceleration) / Delta(current)
```

比較区間は姿勢・速度・摩擦方向を近づけ、入力・測定の時間を合わせる。静止摩擦に捕まった区間、飽和、受信欠落は同定から除外する。電流は可能なら測定値、指令値しか使えない場合はそのモデル誤差を記録する。Ktauを独立に高精度同定できなくても、姿勢別bを直接校正すれば制御の入力ゲインとして使える [R5]。

| テスト条件 | 主な確認 |
|---|---|
| 小慣性・軽荷重・姿勢固定 | 遅延や入力変化に対する振動、電流ノイズ |
| 大慣性・最大想定荷物・姿勢固定 | 到達時間、飽和、最大速度からの制動 |
| 中間姿勢 | 補間の妥当性、非単調な共振・慣性 |
| 旋回＋伸長／旋回＋収縮 | dot(J)、干渉、b0更新、軌道制約変更 |
| 把持／解放付近 | 未知負荷変化と衝撃、出力の連続性 |
| 他軸feedbackの失効 | 高速指令の抑制、有限時間の退避・停止 |

PC検証は実際のJ範囲とその外側の誤差余裕を使う。元説明書のb/b0=0.25〜4は保証範囲ではなく例であり、実際の慣性比がそれを超えるなら試験範囲を広げる。遷移シミュレーションには物理的なdot(J)や結合を含める。Jだけを瞬時変更する試験は故障注入としては使えるが、実際の把持・解放の力学を表したと主張しない。

## 10. Codexへの追加実装条件

変更範囲はCyberGear周辺のみ。RobStrideゲイン・軌道・周期・角度オフセット、共有CAN仕様、上位の動作順・完了条件は変えない。他軸の状態を利用するときは読み取り専用のスナップショットとし、既存の角度変換と単位が正しいことを人間が確認する。原点未確定値を姿勢モデルへ渡さない。

追加モジュール候補：`cybergear_dynamics.*`。HAL非依存で、姿勢と有効性から `J_hat/b0`, `J_hi`, 加速・減速制約、モデル信頼状態を出力する。確定していないリンク寸法・質量・許容値は設定必須とし、もっともらしい数値を埋めない。

他軸の将来軌道・荷物状態が既存インターフェースから得られない場合、上位CANに勝手に項目を追加しない。保守的な荷物・姿勢到達範囲を使う。将来的な全軸協調や「縮めて旋回してから伸ばす」動作は改善候補メモにとどめる。

追加ログ：`posture_snapshot`, 各軸の時刻・有効性、`J_hat`, `J_hi`, `b0`, `b0_rate`, `A_accel`, `A_brake`, 軌道再計画理由、ESO再表現前後の値、電流余裕、補償・振幅・スルー飽和フラグ。

モデル情報の失効時にJ_hatを瞬時にJ_maxへ変更してはならない。検証済みの固定パラメータへのbumplessな退避、または制動状態を使う。姿勢予測の不確かさが安全範囲を超える場合は新規高速移動を拒否する。慣性モデルの異常で自動再armしない。

追加単体テスト：J/bの正値・範囲、補間連続性、時刻wrap・情報失効、モデル更新時の予測加速度整合、電流連続性、同一目標中の制約変更、位置・速度・加速度連続性、飽和中のESO、既知FFとESOの二重補償がないこと、CyberGear以外の指令値・送信回数の不変。

推奨順序は「既存の保護と軌道FFを低速度で確認 → 慣性範囲を概算 → 姿勢依存軌道制約 → b0スケジュールとESO整合 → 最小／最大／遷移条件で速度を上げる」。最初からオンライン同定・高帯域ESO・全逆動力学を同時実装しない。
