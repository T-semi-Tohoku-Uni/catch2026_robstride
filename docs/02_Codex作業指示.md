対象：`T-semi-Tohoku-Uni/catch2026_robstride`、基準ブランチ `fix`  
基準コミット：`2a888ed1e31dda6a063dd62f70259de9111d552a`

## そのまま渡せる指示

このリポジトリのCyberGear制御を、添付 `01_改修説明書.md` に従って高速化・安定化してください。現在は電流モード＋ADRCです。古い運動制御PD版を前提にしないでください。目的は、有限のオーバーシュートを許容して移動を速くし、実機の試行錯誤を減らすことです。安全可動域を越えるオーバーシュートや持続／成長する発振は許容しません。

**最初の応答では実装方針と変更ファイルを示し、その後は下記の小さい変更単位で進めてください。基準との差分や人間の未コミット変更を上書きしないこと。**

### 0. 作業開始時の確認

`git status` とHEADを記録し、基準コミットとの差分を確認する。既存のローカル変更を保持し、担当者が並行して変更したコードを戻さない。必要なCMake設定・ツールチェーン・テスト環境を読んで、実際に使えるビルドコマンドを決める。説明書にないバグを見つけても範囲外なら修正せずメモへ追記する。

### 1. 変更範囲を限定する

変更可能なのはCyberGearのドライバ・外側制御・軌道生成・そのテストとログ。`main.c` はCyberGear用の起動、受信ディスパッチ、タイマ呼出し、専用診断の接続箇所だけを編集する。新規モジュールをビルドに追加する最小変更は許可する。

次は変更しない：RobStride制御、ID 3/4/5の値・周期・モード、`target_angle[1..3]` の解釈、既存角度オフセット、上位CAN ID/DLC/endian、全体の初期化・return仕様、共有CAN速度・自動再送・IRQ優先度、GPIO割当、全体reset処理。全体整形やCubeMX再生成もしない。

CyberGearの入力は従来どおり `target_angle[0]`。返す角度の座標系・原点定義を変えない。範囲外NaN等へのCyberGear側保護は追加するが、他軸の受信処理を書き換えてはならない。

### 2. C1：観測・保護・状態管理

制御式と通常の100 Hzを維持し、以下を追加する。

- 故障理由、rx_sequence、受信時刻、制御時刻、TX成功／失敗、FIFO空き、更新時間・データ鮮度、電流振幅／スルー制限のログ。
- `HAL_OK` を実機到達済みとみなさない送信状態。STOP要求、送信、Reset確認、機械的静止を区別する。
- CyberGear専用状態機械と送信所有権。FAULT後の通常指令・自動再armを禁止し、期限付きSTOP再試行を行う。
- `0x7005` のreadback。`feedback.mode==2` をrun_modeの確認と誤認しない。
- type 17/21が、main.cの既存type 2限定フィルタより前でCyberGearに振り分けられる接続。RobStrideへの従来条件は保存する。
- NaN/Inf、機械範囲、過大dt、位置飛び、拘束疑い、温度、速度、通信失効の保護。未承認の機械上限値を適当に確定しない。

継続運転中の一般readbackや診断フレームは帯域・送信スロットを管理する。STOPと通常電流フレームを同時に大量投入しない。共有FDCANの全キュー破棄は他軸を巻き込むので禁止する。

### 3. C2：HAL非依存の軌道生成

標準は説明書の制約付き五次軌道とする。静止端点用の解析的T、任意初期qd/vd/adからの再計画、全区間の位置・速度・加速度・jerk制約の検証を実装する。同一目標の反復受信では軌道をリセットしない。走行中の目標変更でq/v/aを不連続にしない。

再計画の反復回数と実行時間に上限を設ける。ISRで未制限の根探索・多項式計画をしない。非同期計画では開始状態と切替状態の時刻の一致を保証する。実行可能な軌道が見つからない場合は直前軌道を無期限に走らせず、定義済みの制動状態へ移る。

### 4. C3：2自由度制御

次の式を採用する。最初はwc=4、zeta=2、wo=10を維持し、軌道とフィードフォワードの効果を切り分ける。電流上限・ソフト可動域は人間の承認値を使う。

```text
i_track = (ad + wc*wc*(qd-z1) + 2*zeta*wc*(vd-z2)) / b0
i_dist = bounded_rate_limited(-gamma*z3/b0)
i_req = i_track + i_dist
i_cmd = slew_limit(amplitude_limit(i_req))
```

制御用単位はrad、rad/s、rad/s²、A、秒に統一する。帯域wc/woはrad/s。Hzとの混同をテストする。`b0` の符号は実機確認事項とし、値・符号の未検証状態で高電流を許可しない。

主制御の観測は位置のみで成立させる。既存の速度フィードバックは診断比較に残す。生の位置差分をDへ直結しない。

### 5. C4：ESO・補償制限

既存の離散ESOゲインはZOH/current observerの係数なので、根拠なく連続時間Euler版へ差し替えない。制限後の電流を戻す既存の正しい構造を維持する。未送信電流を印加入力としない。同じ測定で重複補正しない。

外乱補償に上限・変化率上限を持たせ、誤差依存リークからの変更は独立比較可能にする。ESO更新を単純に飽和中ずっと凍結する方式は採らず、制限後入力とモデル妥当性に基づいて処理する。拘束・長時間飽和・進行不足は停止条件とする。

受信時刻での推定と制御時刻への予測を区別する。近似を採用する場合は条件と残留遅延を明記し、テストに遅延を含める。

### 6. C5：任意の200 Hz化と比較モード

100 Hz版で効果を確認後、設定でCyberGearのみphase 0/5の200 Hzへ変更可能にする。TIM6の1 msを変えず、RobStride phase 1/2/3と上位送信phase 9を維持する。

運動制御モードでのPD＋同じqd/vd軌道を比較できる設計は許可するが、走行中に電流モードから自動切替しない。比較モードは停止状態で明示選択・readback・再初期化する。未検証の「最適ゲイン」を自動で作って投入しない。

### 7. テストと成果物

ホストテストでは軌道の連続性・制約、制御の符号と単位、電流制限、ESO係数、重複／古い測定、tick wrap、NaN/Inf、受信フレームのID/DLC/type分岐、TX失敗、停止再試行、モード誤認防止を検証する。添付の `04_数式確認.py` は参考計算であり、実装テストの代わりにはしない。

1000 TIM6 tickで、通常100 Hz版ならCG100回、200 Hz版ならCG200回、各RobStride100回、上位送信100回となる回帰テストを加える。故障状態のときは正常指令数ではなく状態機械の規定どおりになることを検証する。

PCでASan/UBSanと警告を利用できる場合は実行する。少なくとも新規の純C計算部に警告を残さない。`-ffast-math` 等でfinite判定が無効化される設定を採用しない。既存ビルド全体を無断変更せず、必要なら対象ソースの設定と影響をレビューする。

未同定モデルによるシミュレーションを「実機で安定」と記載しない。b/b0の変化、遅延、飽和、摩擦、柔軟性に対する失敗領域も示す。
