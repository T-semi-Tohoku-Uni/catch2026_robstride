# 計測 CSV の解析

保存したログを PC で読み、[analyze_cybergear_calibration.py](../tools/analyze_cybergear_calibration.py) で入力ゲインと停止・通信の観測結果をまとめる。Python 3 の標準ライブラリだけで実行でき、モーターへの接続や設定書換えは行わない。

```powershell
py -3 tools/analyze_cybergear_calibration.py capture.csv --json observation.json
```

`capture.csv` は計測ファームウェアの UART 出力を保存したファイル。`#` で始まる説明行と、試行間に再掲された同じ CSV ヘッダーは読み飛ばす。同じ起動内の複数試行をまとめて解析できる。異なる電源投入・再起動のログは別ファイルにする。戻り値 0 は解析処理の完了であり、実機設定の合格を意味しない。CSV 不正・ファイルエラーは戻り値 2。

`trial_id` が変わる境界では、手動待機中に記録されなかった時刻・受信連番を欠落と判定しない。連続性検査と受信間隔の集計は各試行内で行う。試行途中の欠落は引き続き拒否する。

## 最初に見る項目

1. `quality_issue_rows`：古い受信、重複、連番欠落、ログ欠落、送信失敗、故障、飽和があると、その BASELINE/PULSE 区間は入力ゲインの算出対象から外れる。同じ試行の後続状態で故障・ログ欠落・送信失敗を記録した場合も、先のゲイン観測は採用しない。測定点を間引いて欠落を隠さない。受信連番の飛びは受信がログ周期より速い場合にも起こり、CAN 欠落と断定するものではないが、未記録点を推測せず保守的に拒否する。
2. `input_gain_pairs`：`accepted=true` の `signed_b_rad_s2_per_a` が、その姿勢・荷物・電流・速度付近の観測値。**負なら絶対値にせず、正負座標と電流方向を調べる**。`accepted=false` の試行は `reasons` を確認する。短い移動で量子化に埋もれる場合も値を採用しない。
3. `b_fit_standard_error_rad_s2_per_a` と `windows[].fit_rmse_rad`：位置の二次近似に対する誤差。実電流誤差・CAN 遅延・摩擦・荷物変化は含まれないため、安全余裕へ直接置き換えない。
4. `stop_observations`：`stationary_observed=true` は、記録された速度が静止判定幅に一定時間入ったこと。`observed_forward_distance_rad` は初期移動方向の最大変位、`observed_absolute_travel_rad` は記録点間の総移動量。停止未確認なら距離は途中までの観測である。
5. `rx_age_ms` と `feedback_interval_ms`：受信の鮮度と受信時刻間隔の最小・中央値・95 パーセンタイル・最大。モーターの測定時刻からの遅延、指令到達遅延、最悪応答時間の保証ではない。

`windows` の BASELINE は直前の基準電流区間、PULSE はその次の一定電流区間。受信到着時刻を中心化・尺度化し、位置に `q=c0+c1*t+c2*t²` を最小二乗で当てはめて `a=2*c2` を求める。位置の生データを二階差分する方式ではない。同じ `trial_id` で隣接する区間だけを対応させ、時刻・位置・速度が離れた組は拒否する。

```text
b_observed = (a_pulse - a_baseline) / (i_pulse_command - i_baseline_command)
```

この差分は近傍の一定外乱加速度を差し引く近似。スティックスリップや速度依存摩擦、姿勢変化は残り得る。標準誤差には、残差がゼロでも位置量子化幅 / √12 の誤差床を置く。短時間の曲率が分解できないデータから確実な b0 を出さない。

BRAKE の後に同じ試行の COAST/STOPPING/DONE が続く場合は、静止継続の確認のため連結する。`phases_included` で含まれた状態を確認する。`observed_mean_deceleration_rad_s2` は最初の記録速度から静止判定開始時点、または記録終端までの平均。制動開始以前の指令遅延、記録開始前の移動は含まない。COAST を含む平均を能動制動能力とみなさない。

## 本番設定への扱い

| 本番パラメーター | ログから得られる材料と、残る確認 |
|---|---|
| `B0_FIXED` | 正負それぞれの局所 b 観測。繰返し差、摩擦、負荷、電流到達の不確かさを確認して代表値を決める |
| `B0_MIN/MAX` | 同じ姿勢・荷物の観測分布。全到達姿勢・最大荷物の最悪値をこの一試行から決めることはできない |
| `BRAKE_GUARANTEED_RAD_S2` | 停止区間の減速度と変位の観測。電源・回生・摩擦・慣性の最悪条件に対する保証は別途必要 |
| `OUTWARD_ACCEL_RAD_S2` | PULSE/BASELINE の加速度。遅延中の最悪外向き加速度を網羅する測定ではない |
| `STOP_MARGIN_RAD`、`position_jump_rad` | 位置残差、通信間隔、停止変位。機構の余裕・量子化・遅延不確かさを別に加味する |
| 可動域、電流・速度・温度の許容上限 | 図面・定格・機械設計から先に決める。観測最大値をそのまま許容値にしない |

JSON の `signed_b_observed_rad_s2_per_a` は採用した観測値の分布であり、`B0_MIN/MAX` への設定提案ではない。解析ツールは config を生成・更新しない。`relative_excursion_observed_rad` も移動記録の範囲であり、未記録区間を含む可動域の保証ではない。

現在の計測ファームウェアは許可電流を超える設定を事前に拒否し、ソフトで振幅をクリップしないため、CSV の `saturated` は 0 を出力する。これは**実測電流の到達やモーター内部の電流制限・フィルター・飽和を確認した値ではない**。計測処理は電流上限レジスターの設定変更も行わない。したがって、解析した指令電流基準の入力ゲインには内部制限の影響が残り得る。

## 解析オプション

以下は**オフライン解析の採否条件**。ファームウェアの回転範囲や電流などの動作上限を変更するものではない。全ての採否条件は JSON の `options` に残る。たとえば `--settle-ms 30` のように指定する。数値を緩めて採用した場合は、その理由も測定記録に残す。

| オプション | 既定値 | 意味 |
|---|---:|---|
| `--min-samples` | 6 | 二次近似に必要な新しい測定点数。最低 4。増やすと短い区間を拒否しやすい |
| `--settle-ms` | 20 ms | 各区間の先頭・末尾から除外する幅。指令切替や遅延を避ける。残った点の受信時刻で選ぶ |
| `--max-window-ms` | 250 ms | 二次近似する局所区間の最大幅。BASELINE は末尾側、PULSE は先頭側を使う |
| `--max-rx-age-ms` | 30 ms | ログ時刻と最新フィードバック受信時刻の許容差 |
| `--max-gap-ms` | 30 ms | 新しいフィードバック時刻間の許容最大間隔。連番欠落は幅以内でも拒否 |
| `--max-current-variation-a` | 0.001 A | 近似区間内で一定電流とみなす指令最大値－最小値。スルー中を一定電流として扱わない |
| `--min-current-step-a` | 0.02 A | BASELINE と PULSE の指令電流差の最小絶対値。小さい分母による増幅を避ける |
| `--max-fit-rmse-rad` | 0.001 rad | 位置二次近似の許容 RMS 残差。振動・外れ値・非一定加速度の疑いを検出 |
| `--position-resolution-rad` | 25/65535 rad | 位置量子化幅。標準誤差が過小にならないための下限。外部変換した CSV では変換後単位に合わせる |
| `--min-accel-snr` | 3 | 加速度差の絶対値 / 合成標準誤差の下限。小さい曲率を識別できない場合は拒否 |
| `--max-pair-gap-ms` | 1000 ms | 対応する BASELINE/PULSE の近似中心時刻差の上限 |
| `--max-pair-position-rad` | 0.1 rad | 対応する近似中心位置の差の上限。重力・姿勢差を抑えるための採否条件 |
| `--max-pair-velocity-rad-s` | 0.25 rad/s | 対応する近似中心速度差の上限。速度依存摩擦の差を抑えるための採否条件 |
| `--stationary-speed-rad-s` | 0.03 rad/s | 停止記録の静止判定速度幅。最初からこの幅内なら減速度は求めない |
| `--stationary-dwell-ms` | 100 ms | 静止判定幅内で新しいフィードバックが継続する必要時間 |

## CSV の列

| 列 | 単位・内容 |
|---|---|
| `timestamp_ms` | ログ作成 HAL tick、32 bit、ms |
| `feedback_timestamp_ms` | その位置・速度を受信した HAL tick、32 bit、ms。モーター内部測定時刻ではない |
| `rx_sequence` | 位置・速度フィードバックの受信連番、32 bit。重複・逆行・飛びを検出 |
| `trial_id` | 同じ BASELINE/PULSE/BRAKE/COAST に付く試行 ID |
| `phase` | `BASELINE` / `PULSE` / `BRAKE` / `COAST` などの状態名。大文字・小文字は不問 |
| `position_rad` / `velocity_rad_s` | フィードバックの位置 [rad]・速度 [rad/s] |
| `command_current_a` | 最後に正常キュー投入した電流指令 [A]。実測 iq やモーターへの到達 ACK ではない |
| `fault` / `saturated` | 非ゼロなら当該区間を拒否。現行 `saturated=0` はソフトのクリップなしを表し、モーター内部飽和を実測していない |
| `dropped` / `tx_failed` | ログ欠落・送信失敗の累積カウンタ。変化した区間を拒否 |
| `feedback_valid`（任意） | 0 は無効。列省略時は 1 とするため、未受信を含むログでは必ず記録 |
| `rx_age_ms`（任意） | 記録された受信鮮度。存在すると timestamp 差との一致も検査 |
| `initial_position_rad`（任意） | 起動時に捕捉した固定位置 [rad]。相対移動量の集計基準。捕捉前は空欄にする。同一ファイル内で値が変われば入力エラー。列省略時は最初のログ位置 |
| `temperature_c`（任意） | モーターフィードバック温度 [℃]。現行 CSV に記録するが、解析器は入力ゲイン計算や安全上限決定には使わない |

他の列は許可し、入力ゲイン計算では使用しない。ログ時刻の順序を並べ替えずに読む。32 bit の通常 wrap は展開する。NaN、無限大、符号不正のカウンタ、列欠けは入力エラーとして停止する。

## 空試験

```powershell
py -3 tests/test_calibration_analysis.py
```

合成した位置・速度・電流・時刻だけを使い、符号、基準加速度の差引き、量子化、欠落・重複・古い値・故障・飽和の拒否、時刻 wrap、静止継続と不完全な停止記録を検査する。合成データの数値はロボット設定へ転記しない。
