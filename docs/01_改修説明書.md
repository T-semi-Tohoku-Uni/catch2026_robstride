## 1. 結論と実装順序

**第1案は、現行の電流モードを維持し、「制約付き軌道生成＋速度・加速度フィードフォワード＋補償量を制限したESO」に変更すること。帯域を上げる前に、移動速度と閉ループ剛性を分離する。**

現行コードは既に電流モード＋外側ADRCである。古い運動制御モードの `Kp=8, Kd=4` を前提にした単なるゲイン変更は、今回のコードには適用できない。[S1][S2]

実装は、まず保護・ログ・通信状態を整え、次に軌道と制御則を変更する。その後に速度上限を段階的に上げ、最後に必要な範囲だけ減衰比・制御帯域を調整する。内蔵位置モードの再採用、高帯域ESO、オンライン慣性同定、摩擦の強い不連続補償を同時投入しない。

運動制御モードの内蔵PDは比較・退避用に残す。ただし走行中の自動モード切替は実装しない。モード変更は明示的な停止・確認・再初期化を伴う手動操作にする。

## 2. 現行コードから分かったこと

### 2.1 実際の処理経路

初期化要求受信後、`cybergear_base_init()`、速度モードによる `cybergear_homing()`、RobStride初期化、`cybergear_start_position_adrc()` の順に進む。最後にTIM6を開始する。ADRC起動処理はSTOP、電流モード書込み、電流ゼロ書込み、ENABLEを行う。[S1][S2]

TIM6のベース周期は、コードの80 MHzクロック設定と `Prescaler=79, Period=999` から1 msと計算される。しかしCyberGearを呼ぶのは10相のうちphase 0のみなので、**通常のCyberGear指令周期は10 ms＝100 Hz**。1 kHz制御ではない。RobStrideはphase 1/2/3、上位への角度送信は10相終了時である。[S2][S4]

UARTログはmainループで出力され、制御はTIM6割込みにある。「printfの出力時間がそのまま制御周期になる」という旧構造の診断は、この版には当てはまらない。ただし割込みマスク区間や同優先度ISRの長時間実行は別問題である。[S2][S4]

### 2.2 速度を制限している設定

| 設定 | 現行値 | 評価 |
|---|---:|---|
| `CYBERGEAR_ADRC_REFERENCE_RAD_S` | 0.4 rad/s | 約22.9 deg/s。指令軌道そのものが遅い |
| `CYBERGEAR_ADRC_CONTROL_RAD_S` | 4 rad/s | Hzではない。角周波数の設計パラメータ |
| `CYBERGEAR_ADRC_DAMPING_RATIO` | 2.0 | 公称モデルでは強い過減衰 |
| `CYBERGEAR_ADRC_OBSERVER_RAD_S` | 10 rad/s | 位置から速度・外乱を推定 |
| `CYBERGEAR_ADRC_B0_RAD_S2_PER_A` | 10 | 入力ゲインの仮定。実測根拠はコードから確認できない |
| `CYBERGEAR_ADRC_CURRENT_LIMIT_A` | 10 A | ソフト上限。連続許容電流や安全電流とは同義でない |
| `CYBERGEAR_ADRC_CURRENT_SLEW_A_S` | 5 A/s | 10 msで最大0.05 Aしか変化しない |
| フィードバック失効／更新間隔上限 | 100 ms／50 ms | 高速化時には停止余裕から再評価が必要 |

これらは定義と実装を直接確認した値である。[S1]

0.4 rad/sのランプ指令は、90度移動で最終目標に達するだけでも約3.93秒かかる。これは実機の厳密な最短到達時間ではなく、**内部参照が最終値に達する時間**である。追従遅れや停止判定はさらに別に存在する。

### 2.3 構造的な遅さ：動く目標に対して速度ゼロを追っている

現行制御則は概ね次式である。`z1,z2,z3` はESOによる位置・速度・総外乱加速度の推定値、`r` はランプ化した位置指令である。[S1]

```text
i_req = { wc^2 (r - z1) - 2 zeta wc z2 - z3 } / b0
```

`r` は移動する一方、速度項には `r_dot` がない。したがって移動中も `-2 zeta wc z2` が速度を抑える。完全な外乱補償・正しい公称モデル・非飽和・十分長い等速区間を仮定すると、

```text
q_ddot + 2 zeta wc q_dot + wc^2 q = wc^2 r
定常ランプ追従誤差 e = r - q = (2 zeta / wc) r_dot
```

現行値では係数 `2 zeta / wc = 1 s`。`r_dot=0.4 rad/s` なら **0.4 rad、約22.9度の遅れ**が公称モデルだけでも生じる。実機の観測値ではないが、単純に参照速度を上げると追従誤差まで増える理由を説明する。

また、公称閉ループ極は `s^2+16s+16=0` の根、約 `-1.072, -14.928 [1/s]`。遅い極の時定数は約0.93秒である。安定化のために減衰を増やした結果、停止後の収束も遅くなっている。

### 2.4 発振について確定できる範囲

ログ・慣性・機械共振・実電流がないため、実機発振の単一原因は断定できない。ただしコード上では、電流スルー制限、低帯域の推定速度、未同定の `b0`、サンプル／通信遅延、誤差依存の外乱リークが関与し得る。

電流スルー5 A/sでは、+5 Aから-5 Aへの反転に最短2秒、+10 Aから-10 Aなら4秒かかる。実際にこの電流域を使っているかはログで確認する必要があるが、制動が必要なときに正方向電流が長く残る構造になり得る。

**一方、現行の離散ESOゲインは誤りと決めつけない。** リークを除いた係数は、ZOHモデルのcurrent observerに対する既知の離散極配置と一致する。また、現行コードは制限後の電流を次の予測に戻しており、この点は維持すべきである。[S1][S5]

## 3. 制御モードの整理

本プロジェクトの列挙値と指令APIは以下である。表はコードと公開実装の動作モデルに基づく。搭載ファームウェアの版・内部ゲイン・各制限レジスタの適用範囲は別途確認する。[S1][S3][S6]

| run_mode | 名称 | 主な指令 | どこで制御するか／今回の扱い |
|---:|---|---|---|
| 0 | 運動制御／Operation、MIT-style | 通信type 1で位置・速度・Kp・Kd・トルクFF | 内蔵PDを利用。比較・退避用 |
| 1 | 位置制御 | `loc_ref`, 速度・電流制限等 | 内部位置ループ。過去の発振経験から初回改修では不採用 |
| 2 | 速度制御 | `spd_ref` | 内部速度ループ。現行ホーミングで使用。通常制御への流用は別評価 |
| 3 | 電流制御 | `iq_ref` [A] | 内部電流ループを残し、位置／速度ループをSTM32で実装。第1案 |

### 3.1 運動制御モード

設計上のモデルは次式である。機械座標、トルクの単位・換算、ファームウェアの詳細は実機資料と照合する。

```text
tau_cmd = Kp (q_ref - q) + Kd (v_ref - v) + tau_ff
```

このモードの `velocity` は「速度上限」ではなく、PD則の速度目標である。位置が移動するのに `velocity=0` を固定すると減衰項が移動を妨げる。運動制御案でも必ず軌道の `q_ref, v_ref` を対で渡す。

利点は、位置・速度フィードバックを使う内側PDをモーター側に任せられ、外部CANの遅延に外側の全PDを載せずに済むこと。欠点は、内部実装・ゲイン上限に拘束され、静摩擦や負荷に対する偏差が残り得ること。外部ESOのトルク補償まで同時投入せず、まずPD＋軌道だけを比較する。

### 3.2 電流モード

電流モードはPWMの直接駆動ではない。内部電流ループは残る。外側は概ね、

```text
J(q, payload) q_ddot = Kt_out iq - tau_load - tau_friction
q_ddot = b0 iq + f,    b0 ≈ Kt_out / J
```

として扱う。慣性変化は総外乱に含められるが、ADRCが任意の慣性変化・遅延・飽和を無条件に吸収できるわけではない。`b0` の符号・範囲、制御遅延、制動能力の確認は必要である。[S5]

### 3.3 `feedback.mode` と `run_mode` を混同しない

現行 `feedback.mode` はCAN ID上位の2ビットから取り出す運転状態で、公開実装では0=Reset、1=Calibration、2=Runとして解釈される。**`feedback.mode==2` は速度モードの証明でも電流モードの証明でもない。** [S1][S3][S6]

現行 `cybergear_set_run_mode()` は書込みのキュー投入成功後にソフト側 `motor->run_mode` を更新する。その値を読むだけでは実機モードの確認にならない。起動時には `0x7005` のreadbackを追加する。

制御モードを変更するときは、制御所有権を状態機械に一本化し、STOP／停止確認、モード書込み／readback、ゼロ指令、ENABLE／Run確認、現在位置での軌道・ESO初期化という順に進める。位置・速度ゼロ指令や現在位置指令の順序はモード別に定義する。停止確認と機械的静止は異なる。

## 4. 推奨制御系

### 4.1 構成

```text
上位位置目標 target_angle[0]
    -> 値・機械可動域の検証
    -> 連続軌道 qd, vd, ad（速度・加速度・jerk制限）
    -> 2自由度PD＋加速度FF＋制限付き外乱補償
    -> 電流振幅・変化率の制限
    -> CyberGear iq_ref

位置feedback -> タイムスタンプ付きESO -> z1, z2, z3
制限後・送信状況を反映した電流履歴 ----------> ESO予測
```

主経路は位置測定のみで成立させる。既存フィードバックの速度値は、まず推定速度の検証・異常検出用にログへ残す。単純な位置差分へD項を置き換えない。±12.5 radを16ビットに変換する現行プロトコルでは、位置1カウントは約0.0003815 radであり、差分は周期を短くするほど量子化を増幅する。[S1]

### 4.2 制御則

```text
kp_acc = wc^2
kd_acc = 2 zeta wc

i_track = { ad + kp_acc (qd - z1) + kd_acc (vd - z2) } / b0
i_dist  = bounded_and_rate_limited( -gamma z3 / b0 )
i_req   = i_track + i_dist
i_amp   = clamp(i_req, -I_max, +I_max)
i_cmd   = clamp(i_amp, i_prev - S_down dt, i_prev + S_up dt)
```

`gamma` は外乱補償の有効度で0〜1。起動直後は0で推定状態を整え、設定時間で滑らかに上げる。通常運転中に目標変更のたびにゼロへ戻してはならない。

`ad/b0` が加速に必要な電流を先回りして供給し、`kd_acc * vd/b0` が移動中の不要な制動を相殺する。理想条件では追従誤差は次式になり、ゲインを上げずに移動参照へ追従できる。

```text
e = qd - q
e_ddot + 2 zeta wc e_dot + wc^2 e = 0
```

これは公称モデル上の性質であり、電流飽和・遅延・モデル不一致があれば誤差は残る。高速化はまず `vd, ad` の設計で行い、`wc` の増加を第一手にしない。

### 4.3 軌道生成：小さく実装し、制約を検証する

実機時間と開発範囲を考慮し、初版は**制約検証付きの五次多項式軌道**を推奨する。最短時間のS字軌道ではないが、位置・速度・加速度を整合した形で生成でき、Cで単体試験しやすい。限界速度がなお不足する場合に、別コミットで検証済みのjerk制限S字生成器へ置換する。

静止から静止への距離 `D=|qf-q0|` の移動では、`s=t/T` として、

```text
q(t) = q0 + (qf-q0) (10s^3 - 15s^4 + 6s^5)
T >= max(1.875 D/Vmax,
         sqrt((10 sqrt(3)/3) D/Amax),
         cbrt(60 D/Jmax))
```

この静止端点条件では、上のTで速度・加速度・jerkの最大値を解析的に抑えられる。例えば90度、`Vmax=1.5 rad/s, Amax=3 rad/s², Jmax=15 rad/s³` なら約1.96秒の参照軌道となる。現行ランプ約3.93秒との比較は**軌道時間のみ**であり、実機到達時間の予測ではない。

走行中に目標が変わる場合は、直前に生成した `qd,vd,ad` を新軌道の初期条件に使う。毎回実測位置へ参照を戻す、速度をゼロへ飛ばす、同一目標フレームごとに軌道を再始動する、といった実装は禁止する。

任意初期状態では、終端 `vf=af=0` の五次式を次で生成できる。

```text
q(t) = q0 + v0 t + (a0/2)t^2 + c3 t^3 + c4 t^4 + c5 t^5
Dq = qf - q0
c3 = 10 Dq/T^3 - 6 v0/T^2 - 1.5 a0/T
c4 = -15 Dq/T^4 + 8 v0/T^3 + 1.5 a0/T^2
c5 = 6 Dq/T^5 - 3 v0/T^4 - 0.5 a0/T^3
```

この場合、静止端点用のTの公式だけでは制約を保証できない。0〜T内の位置・速度・加速度・jerkの極値を検証し、実行可能なTを探索する。速度の極値は加速度の実根、加速度の極値はjerkの実根、jerkの極値はsnapの実根で求める。可動域検証には速度の実根も必要になる。端点も必ず評価する。T増加だけで必ず解けると仮定せず、反復回数と最大時間を設け、不可なら制動状態に入る。

探索はISRで無制限に行わない。候補生成・検証を回数制限付きで実行し、新軌道への切替時点の初期条件と一致させる。main側で非同期生成する場合、作成開始時の状態と有効化時の状態のずれを処理する。タイマ内は有効な係数の評価を基本とする。

### 4.4 電流制限と軌道制約は別物

機械的な滑らかさは主に `Amax,Jmax` で制御する。電流スルーを極端に遅くして代用すると、誤差修正・制動も遅くなる。

ただし5 A/sを即座に大きくするのも避ける。まずログで電流スルー飽和率と符号反転時間を確認する。軌道FFだけの電流変化率は概ね `Jmax/b0` であり、`Jmax=15,b0=10` なら1.5 A/s。滑らかな軌道なら、現行スルー値のままでもFF部分は追従可能である。残りにPD・外乱補償の余裕が必要になる。

スルー飽和が律速と確認できた場合のみ、例えば5→10→20 A/sと段階変更する。これは試験候補であり推奨定格ではない。通常制動で負方向の電流を作る際にも制限が働くことをテストする。非常停止は通常の軌道スルーを経由させず、故障方針に従って駆動停止または外部安全機構を使う。

## 5. ESOの扱い：既存の正しい部分を残す

### 5.1 離散モデル

外乱加速度を1ステップ内で一定とするモデルは、

```text
x = [q, v, f]^T
A(T) = [[1, T, T^2/2], [0, 1, T], [0, 0, 1]]
B(T) = b0 [T^2/2, T, 0]^T
C = [1, 0, 0]
x_pred = A x_prev + B u_prev
e_y = q_meas - C x_pred
x_new = x_pred + L e_y

p  = exp(-wo T)
L1 = 1 - p^3
L2 = 3 (1-p)^2 (1+p)/(2T)
L3 = (1-p)^3/T^2
```

である。現行のリークなし部分はこの形式に一致する。[S1][S5]

予測入力には、振幅制限・スルー制限後の出力を用いる。TX失敗時に未送信の `i_req` を印加入力扱いしない。HAL成功はキュー投入成功にすぎないので、`last_queued_current` と `applied_current_estimate` を区別し、後者には有効性フラグを持たせる。バス異常時はモデルの入力が不明になるため、ESOで帳尻を合わせず停止する。

### 5.2 時刻と受信シーケンス

追加状態は、少なくとも `rx_sequence`, `rx_timestamp`, `observer_timestamp`, `last_control_timestamp`, `last_queued_timestamp`。受信時刻が同一msでも別フレームを識別できるよう、鮮度判定にタイムスタンプだけを使わない。

測定補正は新しいフレームに対して1回だけ行う。古い測定へ何度も補正を掛けない。制御周期と受信周期を別の時計として扱う。待ち時間を50 msで切っても、通常周期が5/10 msなら遅延の影響はその前から出る。

推奨実装は、補正済み状態をその受信時刻で保持し、新測定までの時間を、区間ごとの制限後電流履歴で予測して補正する。その後、制御時刻まで予測したコピーを制御に用いる。これにより未来時刻の推定へ古い測定を現在値として混ぜることを避ける。通信遅延により受信時刻とモーター内の測定時刻は一致しないため、残留遅延は別に計測・評価する。

初版でここまでの時刻整合を省く場合は、100 Hz固定周期・十分小さい受信遅延の条件を明記し、制御時刻へ直近測定を近似配置する。これは近似であり、非同期の可変dtを都合よく混在させない。200 Hz化は遅延分布確認後とする。

### 5.3 外乱リークと補償量

現行は追従誤差に応じて0.5〜0.03 /sのリークを入れる。これは外乱蓄積を抑える一方、保持に必要な補償まで忘れ、定常偏差や非線形挙動の原因になり得る。リークを「必ず悪いバグ」とは扱わない。[S1]

初回A/Bではリークを残したまま軌道・FFのみを変更する。その後の別コミットで、通常運転の誤差依存リークを固定の小リーク、またはリークなし＋外乱補償上限へ置き換える。補償上限を0.5〜1 A等の小さい試験値から始め、必要な保持電流に応じて再評価する。これらも実機許容電流内という条件付きの例である。

長時間の電流飽和・高追従誤差・進行不足は「もっと推定で補う」条件ではなく、拘束・衝突・能力不足の疑いとして停止判定にする。単なる電流飽和でESOを無条件に凍結しない。総外乱には負荷だけでなくモデル誤差も含まれるためである。制限後入力の帰還、補償上限、モデル破綻検出を分けて実装する。

`wo` を上げれば常に堅牢になるわけではない。位置量子化・通信遅延・機械共振とトレードオフになる。初版の候補は現行10 rad/sを中心に8〜12 rad/s程度とし、効果と入力ノイズを比較する。論文の一般的な帯域比を機械的に適用して3〜10倍へ上げない。[S5]

## 6. パラメータ変更計画

値は機体・負荷に応じて確定する。表を「そのまま書き込む最適値」と解釈しない。

| 段階 | 変更 | 維持・確認するもの |
|---|---|---|
| A0 | 保護、ログ、readback、テストの追加 | 現行アルゴリズム・100 Hz・電流制限 |
| A1 | 軌道のqd/vd/ad、2自由度制御を追加 | wc=4, zeta=2, wo=10をまず維持。低い速度で比較 |
| A2 | Vmaxを0.4→0.8→1.2→1.5 rad/s等へ段階増加 | Amax/Jmax、実電流・符号反転、機械余裕を監視 |
| A3 | zetaを2→1.2→1.0へ変更 | wcは固定。0.8前後は十分な余裕確認後の速度優先候補 |
| A4 | 必要ならwcを4→6→8 rad/s等へ | b0範囲・遅延・共振の試験に合格した範囲のみ |
| A5 | 外乱リーク方式、200 Hz化、S字軌道への変更 | それぞれ別変更。効果がなければ戻す |

速度優先でも、位置・速度許容差を極端に小さくして長い整定待ちを作らない。評価用の仮値として位置±0.02〜0.04 rad、速度0.1〜0.2 rad/s以下、50〜100 msの連続成立などを置けるが、**既存上位シーケンスの完了条件を勝手に変更しない**。これは比較ログの指標とし、機械干渉・作業精度から人間が確定する。

制御帯域と慣性の関係も確認する。ESOなしの公称PDで実入力ゲイン比を `rho=b/b0` とすると、実際の自然角周波数は `sqrt(rho) wc`、減衰比は `sqrt(rho) zeta` になる。重い姿勢でbが小さくなると遅く、減衰も弱くなる。これは同定範囲を必要とする理由であり、慣性の軽い状態だけで決めない。

## 7. 周期・CAN・状態機械

### 7.1 200 Hz化する場合の最小変更

TIM6の1 ms自体は変更しない。CyberGearだけphase 0と5に置き、RobStrideのphase 1/2/3、上位角度送信phase 9をそのまま残す。初版は100 Hzのまま比較可能にする。[S2]

```text
phase 0: CyberGear
phase 1: Right RobStride（変更なし）
phase 2: Left RobStride （変更なし）
phase 3: EL05           （変更なし）
phase 5: CyberGear      （200 Hz設定時のみ）
phase 9: 上位角度送信  （変更なし）
```

コード設定からモーターバスはnominal 1 Mbit/sと計算される。拡張Classic CAN 8 byteを余裕込み160 bit/frame、指令1件に応答1件と仮定すると、現状4台各100 Hzで約13%、CyberGearのみ200 Hzなら約16%となる。追加読出し、再送、非同期フィードバック、他ノードの交通を含まない概算であり、アナライザ計測を優先する。[S2][S4]

500 Hzを初回から要求しない。平均バス負荷より、FIFO瞬間詰まり、ISR実行時間、応答の実周期、HAL再入の方が制約になる場合がある。

### 7.2 必須の状態機械

```text
DISARMED
 -> STOP_REQUEST / STOP_CONFIRMED
 -> MODE_WRITE / MODE_READBACK
 -> ZERO_COMMAND / ENABLE_WAIT
 -> OBSERVER_WARMUP
 -> RUN
 -> CONTROLLED_STOP または FAULT_LATCHED
```

別に `HOMING` の所有者を定義する。ホーミング中は速度指令、通常運転中は電流指令、故障中は停止処理のみを許可し、mainとTIM6が相反する指令を出さない。全状態遷移には期限を設ける。

停止要求が成立したこと、STOPがCANへ送られたこと、モーターがReset状態であること、機械軸が静止したことは4つの別状態である。これを一つのboolで代用しない。

TX失敗時は故障理由をラッチし、通常指令を禁止する。停止フレームは期限・回数を制限して再試行する。現行もactive=false後の周期呼出しでSTOPを再発行し得るため、「停止を一度しか試みない」とは断定しない。問題は明示的な停止到達管理・理由・期限・代替安全動作がないことにある。[S1][S2]

**バス断・bus-off時はSTOP送信で停止を保証できない。** またSTOP／iq=0は能動制動・機械的停止を保証しない。電流モードで最後の指令が保持される条件や内蔵通信タイムアウトは、搭載FWで確認する。未確認のウォッチドッグレジスタをCodexに創作させない。ソフト改修外でも、外部非常停止、機械的退避余裕、必要なら制動機構を実機試験の前提にする。

### 7.3 受信ディスパッチの注意

現行FDCAN3コールバックは、共通条件で通信type 2以外を除外した後にCyberGearパーサを呼ぶ。このままCyberGear側にtype 17パラメータ応答やtype 21故障応答を追加しても届かない。[S2]

共通の拡張ID・DATA・8byte検証を通した後、CyberGearの自ID・宛先を確認する専用ディスパッチへ渡し、そこで2/17/21を処理する。その後に既存RobStride用のtype 2制約と処理をそのまま残す。未知フレームをCyberGear用として誤消費しない。

## 8. 機械的制約とホーミング

±12.5 radは通信の表現範囲であり、このロボットの安全可動域ではない。ソフト可動域 `q_min,q_max`、外側保護限界、速度・加速度・電流・温度制約を機体担当者が決める。角度の安易な±pi折返しは、ケーブルや有限可動域がある基部で別経路への回転を生むため禁止する。

制動余裕には検出遅延と電流反転の遅れを含める。単純な `v²/(2a)` だけで停止位置を見積もらない。遅延中に外向き加速度 `a_out` が続く最悪条件の概算は、

```text
v_after = |v| + a_out t_delay
d_margin >= |v| t_delay + 0.5 a_out t_delay^2
            + v_after^2/(2 a_brake) + uncertainty_margin
```

である。ただし電源・CAN喪失時に能動制動が使えない場合、この式の `a_brake` を通常時の値で流用してはならない。

ホーミングは速度モードでセンサ端を両方向に測定し、平均位置へ移動した後、STOP→10 ms→SET_ZEROとする実装である。コメントに静止／整定確認をしないと明記されており、これは意図の可能性がある。[S2]

高速通常制御の改修と同時に、原点の定義や端検出の幾何を変更しない。ただし原点設定後に新しい座標のフィードバックを待つ、現在位置で軌道とESOをリセットする、残留速度がある場合に通常制御へ入らない、という境界の安全確認はCyberGearの起動仕様に含める。静止判定を加えることでサイクル時間が変わる点は人間レビュー事項とする。

## 9. 実機時間を節約する検証計画

### 9.1 PC側で先に終える検証

HAL非依存の制御・軌道計算部をホストビルドできるようにする。既存ファームウェアのテストと、本書添付の数式確認スクリプトは別物である。

| 検証 | 注入条件・確認内容 |
|---|---|
| 軌道 | 正負、短距離、ゼロ距離、反転、走行中目標変更、同一目標反復。位置／速度／加速度の連続性と極値制約 |
| ESO | 離散係数、一定入力、入力制限、測定重複、フレーム欠落、異なる時刻、再初期化 |
| 入力 | NaN/Inf、範囲外、符号、過大dt、tick wrap、古い目標 |
| CAN | モード3・iq_refのbyte列、type 2/17/21、別motor/host、DLC不一致、TX FIFO満杯 |
| 状態 | STOP失敗、モードreadback不一致、enable失敗、起動feedback欠落、再起動、故障後の自動再arm禁止 |
| スケジューラ | 1000 tickでCG=100または200回、各RS=100回、上位=100回。順序と角度変換が不変 |
| 数値モデル | b/b0=0.25,0.5,1,2,4、遅延0/5/10/20 ms、摩擦・負荷段差・ノイズ・拘束・柔軟2慣性モデル |

上記の比率は保証範囲ではなく、弱点を探すためのストレス試験範囲。合格領域を示し、不合格領域を隠さない。剛体モデルだけで実機安定性を宣言しない。乱数seedを固定し、実験条件と失敗ログを保存する。

ゴールデンベクトル例（ID 0x7f、host 0xfe、既存エンコード規約）：

```text
run_mode=3 : ID 0x1200fe7f, data 05 70 00 00 03 00 00 00
iq_ref=1 A: ID 0x1200fe7f, data 06 70 00 00 00 00 80 3f
STOP      : ID 0x0400fe7f, data 00 00 00 00 00 00 00 00
```

これらは既存ソースから導くエンコード確認値であり、実機で受理されたという意味ではない。[S1][S3]

### 9.2 実機試験は4区分に絞る

最初は動作域を確保し、衝突・落下・挟まれを避けられる支持状態で実施する。停止不能や暴走を検出してから人手だけで止める試験計画にしない。

**通信・符号確認。** モードreadback、0電流、位置と速度の符号、正負の小電流に対する動作を短く確認する。未知の大電流パルスを入れない。ログ・停止経路を先に検証する。

**入力ゲインの概算。** 同程度の位置・速度条件で許容範囲内の異なる電流に対する加速度を比較し、`b≈Δacc/Δi` を推定する。差分ノイズを避けるため短区間の速度直線当てはめ等を使う。位置のみを使う場合は局所二次当てはめでもよい。静摩擦で全く動かない区間は同定に使わない。代表的な軽い／重い姿勢の2条件以上を残す。

**同じ動作でA/B。** 低速度で旧制御と軌道FF改修版を比較し、その後、速度だけを上げる。正方向・負方向・反転を含め、原点復帰と他軸の動作条件を合わせる。

**最悪負荷と異常。** 許容した最高速での停止、重い姿勢、目標反転を確認する。通信断・拘束の挙動は、まずモック／ベンチと低エネルギー条件で評価する。通常の高速度・大負荷でいきなり断線試験をしない。

### 9.3 ログと合否

制御周期でリングバッファへ数値を記録し、mainで後送または低頻度排出する。ISR内printfは禁止。バッファ満杯時はログを捨ててdrop数を数え、制御を待たせない。

```text
t_us, state, fault_reason, target, qd, vd, ad, q_meas, v_feedback,
z1, z2, z3, i_track, i_dist, i_req, i_cmd,
amp_limited, slew_limited, rx_seq, rx_age_us, control_dt_us,
tx_queued, tx_failed, tx_fifo_free, busoff, tec, rec
```

速度だけでなく、初回許容帯到達時間、50〜100 ms滞在までの時間、最大オーバーシュート、移動中追従誤差、電流の最大／RMS、スルー飽和率、符号反転時間、振動の減衰、更新周期最大値を比較する。

合否は、承認済みの可動域・電流・温度・遅延制約を守ること、目標固定後の振動が成長しないこと、反転時に制動が遅れ続けないこと、故障時に新規通常指令が出ないことを先に置く。その上で到達時間を短くする。小さいオーバーシュートは許容しても、増大する振動や境界越えを許容しない。

## 10. 人間とCodexの分担

人間は、機械可動域、電流・速度・温度の許容値、原点仕様、実機試験の安全条件、作業完了判定を確定する。Codexは、指定範囲の実装、ホストテスト、回帰テスト、差分一覧、未検証事項を担当する。

各コミットは、C1=観測と保護、C2=軌道、C3=2自由度制御、C4=ESO補償制限、C5=任意の200 Hz化／比較モード、と分ける。上位仕様やRobStrideへ影響が必要なら、その時点で変更を止め、別紙の未承認項目として提示する。

別紙 `02_Codex作業指示.md` を実装作業の入口とする。`03_範囲外の不具合候補.md` は情報共有用であり、まとめて修正する指示ではない。
