# CyberGear 五次軌道のパラメータと実装条件

対象は `Core/Inc/cybergear_trajectory.h` と `Core/Src/cybergear_trajectory.c`。
すべて CyberGear 出力角度と同じ座標・単位を使う。実機の慣性、電源、減速能力を検証した値ではない。

`CgTrajectoryLimits` の設定値は次の意味を持つ。加速度等を電流上限から決める際は追従修正・摩擦・外乱補償の電流余裕を残す。

| 項目 | 単位・許容値 | 意味・調整時の注意 |
|---|---|---|
| `position_min_rad` | rad、有限値 | 可動域の下端。原点・減速機の座標を合わせ、機械端から停止余裕を確保した値を設定する。小さくすると許容域が広がるため、数値的な計画失敗を回避する目的で広げない。 |
| `position_max_rad` | rad、min より大 | 可動域の上端。端点だけでなく途中のオーバーシュートも検査する。軌道が域内でも実位置が追従誤差で外れる可能性は別途保護する。 |
| `velocity_max_rad_s` | rad/s、正値 | 絶対速度の上限。上げると移動が速くなる一方、停止距離・運動エネルギー・追従修正量が増す。まず低い値で加減速と停止を確認する。 |
| `acceleration_max_rad_s2` | rad/s²、正値 | 加速能力の上限。慣性上限と使用可能トルクから保守的に求める。高くすると加速 FF と電流要求が増す。 |
| `braking_max_rad_s2` | rad/s²、正値 | 減速能力の上限。加速と別に設定する。初版は両者の小さい方を全区間の絶対加速度上限に使うため、速度の符号反転付近も安全側に判定する。より大きい側の性能は使い切らない。 |
| `jerk_max_rad_s3` | rad/s³、正値 | 絶対加加速度の上限。小さくすると加速度変化が緩やかになり、FF 電流変化率と柔軟振動を抑えやすい。固定 b0 なら FF 電流変化率は概ね jerk/b0。b0 変化時はこの式だけで電流スルーを保証できない。 |
| `duration_min_s` | s、1 µs 以上 | 候補時間の下限。通常は制御周期以上に設定する。さらに距離・速度・加速度・jerkから必要な下限を算出するため、この値を小さくしても各運動制約は解除されない。 |
| `duration_max_s` | s、min 以上 | 候補時間の上限。長くすれば必ず実行可能になるわけではない。走行中の再計画では初期速度・加速度により、長い軌道ほど可動域を越える場合もある。探索失敗は呼出側の故障・停止処理へ渡す。 |
| `target_tolerance_rad` | rad、0 以上 | 新旧目標の差がこの値以下なら古い終点を保持し、同じ制約で再始動しない。位置フィードバックの許容誤差・作業完了条件ではない。大きくするとその分の小移動指令を無視する。制約が変われば同一目標でも再計画する。 |
| `search_iterations` | 回、2～256 | 候補時間の検査回数上限。下限から上限まで対数間隔で探索する。多くすると狭い実行可能区間を見つけやすいが main の演算時間が増す。探索は最短時間の証明でも完全な可解性判定でもなく、見つからなければ失敗する。 |

静止始点では説明書の解析式を初期候補時間に使う。移動始点では直前の生成位置・速度・加速度を引き継ぎ、終端速度・加速度がゼロの五次式を候補ごとに構築する。始点 jerk は引き継がない。接続前後の jerk はそれぞれ制限内だが、jerk 自体の連続性や snap 上限は保証しない。始点が新しい速度・加速度制約の外にあるとき、値をクリップしてつなぐことはせず失敗する。

係数は正規化時刻 `s=t/T` の倍精度で保持する。位置の検査には速度の四次式、速度には加速度の三次式、加速度には jerk の二次式、jerk には snap の一次式の根を使う。根の探索は導関数の根で分けた単調区間の二分法で、各区間最大 56 回、再帰深さ最大 4。重根付近の丸めに備え、高次導関数の臨界点も追加評価する。各項の両端点も検査する。時刻の等間隔サンプルによる合否判定ではない。

丸め許容は内部で `64*DBL_EPSILON*max(1, 係数絶対値和)` とし、その値が検査幅の代表値の `1e-8` を超える悪条件の候補は拒否する。これは倍精度の評価誤差を扱う値で、機械の許容域を調整するパラメータではない。出力は既存制御に合わせて float とする。

`cg_trajectory_plan()` と `cg_trajectory_validate()` は main でのみ呼び、タイマ割込みは `cg_trajectory_evaluate()` / `cg_trajectory_advance()` による評価だけを行う。計画には除算・平方根・指数・対数・倍精度演算が含まれる。反復回数の上限は実時間の締切を保証しないので、呼出側は未来の切替時刻・実行期限・失敗停止を管理する。ISR が移動を進めている途中の古い状態から作った係数を、そのまま現在時刻で有効化してはならない。

`reset()` は非ゼロ初期速度・加速度も保持し、jerk はゼロにする。非ゼロ初期状態のまま計画せず時刻を進める操作は失敗する。`evaluate()` の時刻は現在の点からの相対時間ではなく、軌道開始からの経過秒。終了済み軌道は終点・速度ゼロ・加速度ゼロを返す。同一目標の繰り返しで `elapsed_s` は戻らない。すべての公開関数は失敗時に軌道と出力先を変更しないため、呼出側で明示的に故障をラッチし、旧軌道を無条件に継続しない。

ホスト試験 `tests/trajectory_test.c` は、静止端点の解析時間、同一指令、反転、制約変更、位置・速度・加速度の接続、四つの位置極値、失敗時の非変更、400 組の決定的乱数初期条件と各成功軌道 2049 点の高密度照合を行う。係数生成とは独立した 200 組の乱数多項式も各 4096 点で照合する。これらは数値計算の検証であり、実機の制動・通信遅延・振動・電流性能を保証しない。
