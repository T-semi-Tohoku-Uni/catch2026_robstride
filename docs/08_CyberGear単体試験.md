# CyberGear単体試験・シリアル調整

単体試験は、UARTから明示的に開始したときだけ原点探索と往復動作を行います。
初期設定では原点基準で **+60度 → -60度 → +5度 → -5度** を繰り返します。
60度は片側振幅で、全幅は120度です。

起動時の設定は`Core/Inc/cybergear_config.h`にまとめています。
単体試験では、21項目をUARTから変更して再初期化できます。
**UART変更はRAM内だけに保持され、ヘッダーやFlashを書き換えません。電源断・MCUリセットで既定値に戻ります。**
通常4軸運転では、このシリアル調整機能を使いません。

## 接続と端末設定

- CyberGear：CAN3（RX PA8 / TX PA15）、モーターID `0x7f`、ホストID `0xfe`。
- 原点センサー：PA0。原点探索に必要です。
- USB-UART：TXをUSART2 RX PA3へ、RXをUSART2 TX PA2へ接続し、GNDを共通にします。
- 端末：115200 bps、8データビット、パリティなし、1ストップビット、フロー制御なし。
- 行末：EnterでCR、LF、CRLFのいずれかを送信します。設定キーは小文字で入力します。

CyberGear通信用のCAN3は必要です。基板間CAN1、RobStride ID 3・4・5、そのPC0/PC1入力・EXTIは単体試験で使用しません。
他軸の応答を待たず、RobStrideにはSTOPを含めて送信しません。接続されている他軸は試験前に停止させてください。

起動すると`UART console ready`を表示して待ちます。
`s`、有効な`set`、`reinit`の明示的な指令で初めてCAN3通信とモーターハンドラーの初期化を進めます。
UART未接続・未入力、`show`・`help`だけの場合は、モーターの初期化・原点探索・往復動作を開始しません。

## コマンド

| 入力 | 行末 | 動作 |
| --- | --- | --- |
| `s` または `S` | Enterが必要 | 停止確認・初期化後、原点探索と往復動作を開始 |
| `x` または `X` | 不要 | 停止要求。原点探索中にも有効 |
| `set KEY VALUE` | Enterが必要 | 値を検査し、停止確認・再初期化に成功した場合に設定を反映。その後は開始待ち |
| `reinit` | Enterが必要 | 現在の設定を維持して停止確認・再初期化。その後は開始待ち |
| `show` | Enterが必要 | 反映済みの設定値と各項目の説明を表示 |
| `help` または `?` | Enterが必要 | キー・反映済み設定値・各項目の説明を表示 |

**開始には改行が必要です。** 以前の1文字受信による開始から変更しています。
`set ...`の先頭の`s`だけで動き出すことを防ぐため、開始は`s`または`S`だけの行で判断します。
空行は無視します。`set`・`reinit`・`show`・`help`と設定キーは小文字で入力してください。

`x` / `X`は行の途中でも停止要求として扱います。
停止後に`s`だけを送っても再始動しません。`reinit`または有効な`set`を実行し、成功後に新たな`s`を送ります。
`reinit`は設定値の初期値への復帰やMCUリセットではありません。

## 最初の試験と設定変更

初期設定で開始するには、起動メッセージを確認して、次の1行だけを送ります。

```text
s
```

停止応答・静止を確認した後、PA0で原点探索し、往復を開始します。
原点探索中や再初期化中は、`x` / `X`以外の入力を使わないでください。その間のコマンドは破棄されます。

例えば動作中の電流上限を2.5 Aに変更する場合は、次のように進めます。

1. 次の1行を送ります。

   ```text
   set current 2.5
   ```

2. `stopping; waiting for fresh STOP and stationary feedback`に続き、
   **`ready; send s + Enter to home/start`** が出るまで待ちます。
   この時点で設定は反映されていますが、モーターを再び有効化しません。
3. 必要なら`show`とEnterで反映済みの値を確認します。
4. 新たに`s`とEnterを送り、原点探索から試験を再開します。

**再初期化をまたいで複数のコマンドを一括貼り付けしないでください。**
`set`は1項目ずつ実行し、その都度`ready`を待ちます。`set ...`と`s`を同時に送る使い方はできません。
UART受信は割込みで蓄積しますが、長い貼り付けを無制限には保存しません。
既定の1行容量は終端込み96バイト、受信リングは256バイトです。
長すぎる行・受信エラー・受信あふれは破棄し、破棄した行の末尾を開始指令として扱わないようにしています。

## 停止確認と失敗時の動作

有効な`set`と`reinit`は、次の処理を必ず経由します。

1. 周期制御を止め、CyberGearへ新しいSTOPを要求します。
2. STOP要求後の新しい停止モードのフィードバックと静止状態を確認します。
3. 送信待ちのCANフレームがなくなったことを確認します。
4. 制御・観測器・軌道などの状態を初期化し、設定を反映します。
5. 無励磁の開始待ちに戻ります。原点探索・往復は新たな`s`を受信した場合だけ開始します。

数値が不正、未知のキー、範囲外、設定同士が矛盾する場合は、設定全体を変更しません。
**無効な`set`は停止指令ではないため、動作中ならそのまま動作を続けます。** 停止する場合は`x`を送ってください。
小数や指数表記は数値項目で使えますが、`dwell_ms`・`leg_ms`は整数だけです。
`NaN`・`Inf`、数値の後ろの余分な文字、整数の桁あふれは受け付けません。

`STOP unconfirmed`や`reinit failed`の場合は、候補の設定を反映せず、以前の設定を保持します。
自動で起動せず、停止確認を飛ばして原点探索にも進みません。
電源・CAN3配線・モーター応答を確認し、`reinit`を実行してください。
成功して`ready`が表示された後も、再試験には`s`が必要です。

`x` / `X`はソフトウェアの停止要求です。受信後、制御・探索処理からSTOPを送ります。
通信やソフトウェアが動作しない状況まで停止を保証する物理非常停止ではありません。
UART切断そのものも停止指令にはなりません。

## 調整できる21項目

表の初期値・上限は現在の`cybergear_config.h`に対応します。
ヘッダーを変更して再ビルドした場合は、そのビルドの値が基準になります。
表の範囲内でも、予約電流などとの整合検査で拒否する場合があります。

| キー | 初期値 | UARTから受け付ける範囲 | 意味・変更時の影響 |
| --- | ---: | --- | --- |
| `current` | 3 A | `0 < current <= 6` | 往復ADRCの総電流上限。増加すると出せる力と発熱が増える。補償・予約・停滞判定の電流も連動 |
| `speed` | 0.3 rad/s | `0 < speed <= 0.4` | 参照軌道の速度上限。下げると移動時間が長くなる |
| `wc` | 4 rad/s | `0 < wc <= 20` | 位置制御帯域。位置ゲインは`wc²`。増加で応答が速くなる一方、電流変動・振動が増え得る |
| `zeta` | 2 | `0 < zeta <= 10` | 減衰比。速度ゲインは`2*zeta*wc`。増加で速度への減衰が強まり、整定が遅くなる場合がある |
| `wo` | 6 rad/s | `0 < wo <= 10` | 観測器帯域。低下で位置ノイズの影響が減る一方、負荷変動の推定が遅くなる |
| `b0` | 1 rad/s²/A | `0.35 <= b0 <= 3` | 電流から加速度への代表ゲイン。姿勢・負荷に対する実測を基に調整。軌道計算の下限0.35は変わらない |
| `accel` | 1 rad/s² | `0 < accel <= 1` | 軌道の希望加速度上限。実効値は電流予算でも制限 |
| `brake` | 1 rad/s² | `0 < brake <= 1` | 軌道の希望減速度上限。実機の停止距離を保証する値ではない |
| `jerk` | 5 rad/s³ | `0 < jerk <= 5` | 軌道の加速度変化率上限。低下で反転などが緩やかになる |
| `rise` | 5 A/s | `reserve_slew < rise <= 5` | 符号付き電流が数値として増える速さの上限。電流絶対値の増加率とは異なる |
| `fall` | 5 A/s | `reserve_slew < fall <= 5` | 符号付き電流が数値として減る速さの上限。正負の制動にも作用 |
| `dist_fraction` | 0.5 | `0 <= dist_fraction <= reserve_fraction` | 外乱補償の上限を`current * dist_fraction` Aにする |
| `reserve_fraction` | 0.5 | `dist_fraction <= reserve_fraction < 1` | 軌道生成から補償用に取り置く電流割合。増加すると加減速用の余裕が減る |
| `dist_slew` | 1 A/s | `0 < dist_slew <= 5` | 補償電流の変化率上限。上限5はコンパイル時の電流増加率設定に由来 |
| `reserve_slew` | 2.5 A/s | `0 <= reserve_slew < min(rise,fall)` | 軌道生成から取り置く電流変化率。残りを軌道のjerk計算に使用 |
| `gain` | 1 | `0 <= gain <= 1` | 外乱補償倍率。0でも観測器の推定は続き、補償だけを無効化 |
| `leak` | 0.03 /s | `0 <= leak <= 0.5` | 固定リーク係数。小さいほど保持負荷の補償も誤推定も残りやすい |
| `amp` | 60度 | `small <= amp <= 60`、正値 | 大振幅。正負の端点と試験用の実測位置保護範囲が連動。ソフト位置限界の内側が必要 |
| `small` | 5度 | `0 < small <= amp` | 小振幅。`+amp → -amp → +small → -small`の順に動く |
| `dwell_ms` | 1000 ms | 整数、`0 < dwell_ms < leg_ms` | 到達条件を連続して満たす必要がある時間 |
| `leg_ms` | 20000 ms | 整数、`dwell_ms < leg_ms < 60000` | 1目標あたりの時間上限。移動時間と到達後の待機時間を含む |

3 A・0.3 rad/s・観測器6 rad/sは**起動時の試験設定**です。
UARTでは共通設定の範囲内で、電流を最大6 A、軌道速度を最大0.4 rad/s、観測器を最大10 rad/sまで変更できます。
受け付ける最大値はソフトウェアの設定範囲であり、その機構や負荷で使える電流・帯域を保証しません。
共通の固定上限そのものをUARTで引き上げることはできません。

### 依存する設定の変更順

各`set`の完了・`ready`表示を待ってから、次の1行を送ってください。

- 外乱補償割合を0.6へ上げる場合：先に`set reserve_fraction 0.6`、完了後に`set dist_fraction 0.6`。
- 予約電流割合を下げる場合：先に`dist_fraction`を下げ、完了後に`reserve_fraction`を下げます。
- `rise`・`fall`を2 A/sへ下げる場合：先に`reserve_slew`を2未満へ下げてから変更します。
- 大振幅を5度未満へ下げる場合：先に`small`を新しい大振幅以下へ下げます。
- `leg_ms`を現在の`dwell_ms`以下へ変更することはできません。必要なら先に`dwell_ms`を下げます。

`current`を変更しても、設定済みの補償・予約の割合は維持します。
例えば`current=2.5`・`dist_fraction=0.5`なら、補償上限は1.25 Aです。
電流を下げると軌道生成に使える加減速予算も減るため、`speed`だけで移動時間は決まりません。
振幅・速度を変えたら、待機込みで`leg_ms`に収まるか確認してください。

## 到達判定・原点探索・保護

往復中は、軌道完了・実測位置誤差±0.5度以内・推定速度0.03 rad/s以下を、
`dwell_ms`の間連続して満たした場合にだけ次の目標へ進みます。
UARTから位置・速度の到達判定を緩めることはできません。

試験用の実測位置保護は原点から`amp + 3度`を超えた場合です。初期設定では±63度、
`amp=45`なら±48度でSTOPを要求します。これらは停止要求の境界で、停止完了位置ではありません。
軌道の`speed`は実測速度の保護停止閾値とは別です。
受信途絶、追従異常、持続する電流制限などの保護も引き続き使います。

原点探索は別の速度制御です。既定の探索速度は高速1.0 rad/s・低速0.4 rad/sで、
往復ADRCの`current`・`speed`設定は原点探索には作用しません。
`x` / `X`による停止要求は原点探索中にも処理します。
原点探索速度、通信ID、到達許容誤差、速度・温度・位置の保護閾値、飽和停止時間、UART通信速度などは、
`cybergear_config.h`を編集して再ビルド・書込みした場合に変更されます。

既定の観測器6 rad/sは、位置フィードバックの遅延・揺れによる電流変動を抑えるための値です。
固定リーク0.03 /sと補償上限1.5 Aは、目標付近の保持負荷を補うための既定設定です。
到達しない場合も、到達判定や保護停止を緩める前に`err`・`idist`・`dlim`・`ireq`・`slew`を確認してください。

## ログの読み方

異常・開始失敗・`x`停止時は、診断間隔を待たず状況を1回出力し、その後のUART定期送信を停止します。
実行中だった設定一覧の出力も中断します。UART受信とCANの停止処理は継続します。
次の指示には応答し、`show` / `help`では現在の状況と設定一覧を出力した後、再び無送信で待機します。
`reinit`または有効な`set`による再初期化が成功すると定期診断を再開します。

起動識別文字列は`CG_UART_TUNING_V2`です。シリアル調整対応版では`UART console ready`も表示します。
`show` / `help`の`CG SET キー=値`が反映済み設定です。再初期化に失敗した候補値はここに表示されません。

| ログ項目 | 意味 |
| --- | --- |
| `q` / `v` / `target` | 実測位置[rad]・生の速度フィードバック[rad/s]・最終目標[rad] |
| `err` / `vest` | 最終目標と実測位置の誤差[rad]・到達判定に使う推定速度[rad/s] |
| `done` / `dwell` / `legs` | 軌道完了・到達条件を継続した時間[ms]・完了区間数 |
| `itrk` / `idist` / `dlim` | 追従電流・外乱補償電流・補償上限[A] |
| `dclip` | 外乱補償側の振幅または変化率制限。旧ログの`clipped`に相当 |
| `ireq` / `i_cmd` | 全体制限前の要求電流・最後に送信キューへ入れた電流[A] |
| `amp` / `slew` / `sat_ms` | 全体電流の振幅制限・変化率制限・どちらかが連続した時間[ms] |
| `track` | その時点の参照軌道と実測位置の差[rad] |

定期ログの`amp`は電流の振幅制限フラグです。設定キーの`amp`（大振幅の角度）とは別です。
`fault=4`はホーミング後の管理制御の起動タイムアウトです。
失敗時の`CG startup failed: phase=...`は停止処理に入る直前の段階を示します。
`phase=1`はSTOP応答と静止待ち、`3`は運転モードのreadback待ち、`5`は有効化後のRun応答と静止待ちです。
`CG startup feedback`の`mode`は停止時0・運転時2で、readbackの電流制御モード3とは別です。
`CG startup stationary`は静止速度上限と、直前までの静止判定継続時間を示します。
既定では生の速度が絶対値0.03 rad/s以下で100 ms継続する必要があり、超過すると継続時間をリセットします。
例えば0.038 rad/sはこの条件を満たしません。単発の停止後ログだけでは、実際の微動か速度値の揺れかは判別できません。
`phase`・`mode`・`age`・`readback`と軸の動きを合わせて確認してください。
停止後の`state=7`は停止処理中、`state=8`は故障ラッチです。STOP再試行終了後に`age`が増え続けても、起動失敗の原因が受信途絶だったとは限りません。
`fault=15`は全体電流の振幅制限または変化率制限が既定で1000 ms続いたことによる停止です。
3 A未満でも変化率制限が続けば停止します。`dclip`だけではこの停止理由を判断できません。
停止判定は通常電流の送信前なので、停止時の`i_cmd`は実際の保持電流や停止後の実電流を示すものではありません。

## 有効化・ビルド・書込み

`Core/Inc/cybergear_config.h`の`APP_CYBERGEAR_STANDALONE_TEST`は既定で`1`（単体試験ON）です。
`0`にして再ビルドすると通常4軸制御になります。UARTから起動モードは変更できません。
CMakeの`APP_CYBERGEAR_STANDALONE_TEST=HEADER`はヘッダーに従い、`ON` / `OFF`を明示するとヘッダーより優先します。
過去のビルドディレクトリに`ON` / `OFF`が残っている場合は、`HEADER`で再構成してください。

リポジトリ直下で、CMake・Ninja・標準Cライブラリ付きArm GCCを利用して実行します。

```sh
cmake --preset Debug
cmake --build --preset Debug
```

単体試験を明示的に有効にする場合は、構成コマンドを
`cmake --preset Debug -DAPP_CYBERGEAR_STANDALONE_TEST=ON`にします。
今回検証した書込み対象は`build/Debug/catch2026_robstride.elf`です。
上記コマンドはビルドのみで、基板に書き込みません。
常用する初期値を変える場合はヘッダーを編集して再ビルド・書込みします。
一時的な調整にはUARTを使い、値を残す場合は`show`の出力を記録してください。

## ホスト試験の範囲

ホスト試験では、ヘッダー設定の反映、21項目の数値解析・範囲・依存条件・不正変更時の非更新、
UART行解析と受信あふれ、停止・再初期化の条件、CAN1・他軸との分離を検査します。
既存の目標順序・到達判定・待機・範囲逸脱・故障ラッチ・時刻周回の試験も使います。

制御の合成試験では、±0.94 A相当の一定負荷で既存の到達判定のまま2周完了を確認します。
さらに11 ms周期の受信、指令・位置それぞれ10 msの遅延、振幅0.003 radの位置ノイズに対し、
観測器10 rad/sでの`fault=15`と、6 rad/sで同じ保護・到達条件を使った2周完了を比較します。
これらは実機の負荷・遅延を同定したモデルではありません。
機械許容範囲、実機での停止位置・連続運転の適合性は別途確認が必要です。
