# 統合修正と実機なし検証

2026-09-10。実機接続、書込み、モーター駆動は行わず、ホスト試験とARMクロスビルドで検証した。

## 統合対象

- 作業開始時: `20_cybergear_fix` / `0d15655`。
- `hirayama_fix` / `1ed7d72`: 制御コードの変更はなく、STM32G474RBのDBANK=1用リンカ配置と検証を取り込んだ。
- `fix-robstride-startup-retry` / `1b3dd34`: 全RobStride軸の起動確認、再試行、失敗時停止を取り込んだ。

後者の祖先には古いCyberGear APIを前提とするアプリ全体の分割がある。
競合解消では現行の `main.c` とCyberGear制御・原点探索・単体試験を維持し、
起動処理を `robstride_startup.c` として非ブロッキング化した。
`board_protocol.c` の通信変換も採用した。旧APIを呼ぶ `motor_app.c` /
`cybergear_homing.c` とそれら専用のテスト・仕様書は採用していない。

## 検出した問題と修正

| 問題 | 統合版の動作 |
|---|---|
| 既定がCyberGear単体試験となりRobStride送信をすべて拒否 | 通常4軸を既定にし、単体試験はCMakeで明示選択 |
| CyberGear等の1軸の応答だけで全体を起動済み扱い | RobStride全3軸を個別に停止確認→設定→現在位置保持→有効化→新規mode=2確認 |
| EL05だけ起動後に再有効化 | 起動前の全軸共通再試行に置換。15秒期限後は全軸停止 |
| CyberGearの起動待機中にRobStride応答が失効 | 同じポーリングループでCG状態機械とRSの応答要求を継続 |
| CG先行起動後の1msタイマー割込みで周期異常 | TIM6移行時に初回周期待ちを再設定。5/10ms双方を回帰試験 |
| タイマー停止後のmanaged CG STOP要求が実送信されない | 停止確認中もCG制御stepを実行してSTOP再試行を処理 |
| 3枠TX FIFOへ4軸のSTOPを一度に投入 | 軸を輪番にし、CG制御stepを含め1ポール最大2送信に分散 |
| STOP前の受信を停止確認に使える競合 | 最初に送信成功したSTOPの受信カウンタ基準をIRQマスク内で保存 |
| 一部モーターの通信だけで全軸の健全性を判断 | 運転中は各RSの鮮度・mode・faultとCG状態を確認し、異常時は全軸停止 |
| CAN目標のNaN/infや4軸値の部分更新 | 不正値を含むフレーム全体を拒否し、4値を同じ割込み禁止区間で反映 |
| 任意の開始指令変化で初期化 | 初期化開始は受信した0→1だけ。運転中の復帰動作と2秒無視は維持 |
| 停止距離予測の設定不整合で通常6 A・単体3 Aが起動拒否 | ユーザー指示により予測保護モデル全体を省略。計算・運転時判定・起動検査・専用パラメーターを削除 |
| 静止待機時間の乗算wrap | 設定時に拒否し、起動期限と待機時間の整合性検査を維持 |

起動・停止失敗後の自動リセットや再有効化は行わない。
STOPは最大1秒、送信成功と新しい停止フィードバックを待ち、確認できなければログに残す。
通信が失われた実モーターの停止そのものは、ソフト上の送信成功から保証できない。

## 停止距離予測モデルの省略

2026-09-10のユーザー指示により、停止距離の予測保護モデル全体をいったん省略した。
予測距離の計算・運転中の境界余裕判定・同じ式による起動検査に加え、
`brake_guaranteed_rad_s2`、`outward_accel_rad_s2`、`transport_delay_ms`、`stop_margin_rad`
と対応する設定マクロを削除した。`CG_FAULT_STOP_MARGIN` は過去ログとの番号互換のため宣言だけ残し、発報する実行経路はない。

通常6 A・単体3 Aを停止距離式で起動拒否する条件はない。
角度・速度・電流・温度・通信・追従・拘束の保護とSTOP処理、ADRC・軌道・慣性モデルは維持する。
軌道生成用の加減速電流予算・A/J制約・電流変化率制限も残している。
[現在の設定条件](controller_parameters.md)を参照。
ホスト試験の運転用設定は合成fixtureであり、実機設定へ転記しない。
空試験の合格は実機での運転成功や停止位置を保証しない。

## 検証

macOS / AppleClang 16でホストCTestを実行し、28/28件が合格した。
Cのテスト本体と抽出した実main関数にはASan/UBSan、警告エラー化、assert有効化を適用した。
RobStride起動は19シナリオ、Flash検証器は12ケース。
統合試験ではCG先行100ms / 後発900ms、5/10ms周期、各軸欠落、
タイマー失敗、有限FIFOとSTOP再試行、tick wrapを検証する。
既存のCyberGear制御・軌道・128条件の仮想プラント試験も含む。
停止距離予測の省略後に全件を再実行した。通常6 A・単体3 A・試験用0.5 Aで起動し、
正負0.05 rad/sのフィードバックで制御を継続すること、hard境界では `CG_FAULT_POSITION` となることを確認した。

```sh
cmake -S tests -B build/host-tests -G Ninja -DCMAKE_C_COMPILER=clang -DCYBERGEAR_SANITIZERS=ON
cmake --build build/host-tests
ctest --test-dir build/host-tests --output-on-failure
```

ARM GCC 14.3.1（STM32CubeCLT 1.21.0同梱）で通常Debug/Releaseと単体Releaseをビルドした。
この環境のHomebrew版Arm GCCにはnano.specsがないため、CubeCLTのGNU-tools-for-STM32/binをPATH先頭に使用した。

| ビルド | Bank 1 | Bank 2 | 結果 |
|---|---:|---:|---|
| 通常Debug | 51,256 B | 26,256 B | ビルド・ELF配置検査合格 |
| 通常Release | 37,904 B | 14,976 B | ビルド・ELF配置検査合格 |
| 単体Release | 37,032 B | 15,552 B | ビルド・ELF配置検査合格 |

```sh
cmake -S . -B build/integrated-Debug -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_TOOLCHAIN_FILE=cmake/gcc-arm-none-eabi.cmake
cmake --build build/integrated-Debug
cmake -S . -B build/integrated-Release -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE=cmake/gcc-arm-none-eabi.cmake
cmake --build build/integrated-Release
cmake -S . -B build/integrated-standalone -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE=cmake/gcc-arm-none-eabi.cmake -DAPP_CYBERGEAR_STANDALONE_TEST=ON -DCATCH_FIRMWARE_BASENAME=cybergear_standalone
cmake --build build/integrated-standalone
python3 tests/check_flash_layout.py build/integrated-Debug/catch2026_robstride.elf build/integrated-Release/catch2026_robstride.elf build/integrated-standalone/cybergear_standalone.elf
```

実機のCAN遅延、最悪割込み時間、温度・負荷・慣性、停止距離、原点センサーは未検証。
RS設定書込み後のtype 2応答は受信の証拠であり、設定値そのもののreadback確認ではない。
Flash配置はDBANK=1を前提とし、このセッションでオプションバイトの読出しはしていない。
